# 项目运行流程分析

## 项目概述

这是一个基于TypeScript + React + Ink的交易机器人项目，采用命令行界面(CLI)运行。项目主要功能是提供多种交易策略的自动化执行。

## 与Spring框架的对比

### Spring框架特点
- **架构类型**: Web服务
- **运行模式**: 请求-响应模型
- **生命周期**: HTTP请求生命周期（请求 → 过滤器 → 控制器 → 服务 → 响应）
- **并发模型**: 多线程处理请求
- **状态管理**: 通常为无状态

### 本项目特点
- **架构类型**: 命令行工具
- **运行模式**: 事件循环 + 定时器驱动
- **生命周期**: 持续运行的事件循环
- **并发模型**: 单线程事件循环
- **状态管理**: 有状态，持续维护交易状态

## 项目启动流程

### 1. 入口文件
```typescript
// index.ts
import "./src/index.tsx";

// src/index.tsx
import React from "react";
import { render } from "ink";
import { App } from "./ui/App";
import { setupGlobalErrorHandlers } from "./runtime-errors";

setupGlobalErrorHandlers();
render(<App />);
```

### 2. 应用初始化
- 设置全局错误处理器
- 渲染主应用组件 `<App />`
- 显示策略选择界面

### 3. 策略选择
用户通过键盘选择三种策略之一：
- **趋势跟随策略 (SMA30)**: 监控均线信号，自动进出场并维护止损/止盈
- **做市刷单策略**: 双边挂单提供流动性，自动追价与风控止损
- **偏移做市策略**: 根据盘口深度自动偏移挂单并在极端不平衡时撤退

## 核心运行机制

### 1. 事件循环架构

项目采用**事件驱动架构**，核心运行机制基于：

```typescript
// maker-engine.ts 中的关键代码
start(): void {
  if (this.timer) return;
  this.timer = setInterval(() => {
    void this.tick();
  }, this.config.refreshIntervalMs);
}
```

### 2. 数据流订阅

每个Engine实例在初始化时订阅多种数据源：

```typescript
private bootstrap(): void {
  // 订阅账户信息
  this.exchange.watchAccount((snapshot) => { /* 处理账户更新 */ });
  
  // 订阅订单状态
  this.exchange.watchOrders((orders) => { /* 处理订单更新 */ });
  
  // 订阅市场深度
  this.exchange.watchDepth(this.config.symbol, (depth) => { /* 处理深度更新 */ });
  
  // 订阅价格ticker
  this.exchange.watchTicker(this.config.symbol, (ticker) => { /* 处理价格更新 */ });
}
```

### 3. 核心循环逻辑

每个`tick()`周期执行以下操作：

```typescript
private async tick(): Promise<void> {
  // 1. 检查是否正在处理中
  if (this.processing) return;
  
  // 2. 检查限流状态
  const decision = this.rateLimit.beforeCycle();
  if (decision === "paused" || decision === "skip") return;
  
  // 3. 检查数据就绪状态
  if (!this.isReady()) return;
  
  // 4. 确保启动时订单重置完成
  if (!(await this.ensureStartupOrderReset())) return;
  
  // 5. 获取市场数据
  const depth = this.depthSnapshot!;
  const { topBid, topAsk } = getTopPrices(depth);
  
  // 6. 计算订单策略
  const desired: DesiredOrder[] = [];
  const position = getPosition(this.accountSnapshot, this.config.symbol);
  
  // 7. 根据持仓状态制定订单计划
  if (Math.abs(position.positionAmt) < EPS) {
    // 无持仓：双边挂单
    desired.push({ side: "BUY", price: bidPrice, amount: tradeAmount, reduceOnly: false });
    desired.push({ side: "SELL", price: askPrice, amount: tradeAmount, reduceOnly: false });
  } else {
    // 有持仓：平仓单
    const closeSide = position.positionAmt > 0 ? "SELL" : "BUY";
    desired.push({ side: closeSide, price: closePrice, amount: absPosition, reduceOnly: true });
  }
  
  // 8. 同步订单状态
  await this.syncOrders(desired);
  
  // 9. 风险控制检查
  await this.checkRisk(position, bidPrice, askPrice);
  
  // 10. 触发状态更新
  this.emitUpdate();
}
```

## 生命周期管理

### 1. 初始化阶段
- **构造函数**: 创建Engine实例，初始化配置和依赖
- **bootstrap()**: 订阅数据流，设置事件监听器
- **start()**: 启动定时器循环

### 2. 运行阶段
- **定时器循环**: 每`refreshIntervalMs`毫秒执行一次`tick()`
- **事件处理**: 实时处理交易所推送的数据更新
- **状态同步**: 维护订单状态、持仓状态、风险状态

### 3. 停止阶段
- **stop()**: 清理定时器，停止循环
- **资源释放**: 取消数据订阅，清理资源

## 状态管理机制

### 1. 数据快照
项目维护多个核心数据快照：
- `accountSnapshot`: 账户信息
- `depthSnapshot`: 市场深度
- `tickerSnapshot`: 实时价格
- `openOrders`: 当前挂单

### 2. 状态同步
通过`syncOrders()`方法实现期望订单与实际订单的同步：

```typescript
private async syncOrders(targets: DesiredOrder[]): Promise<void> {
  // 1. 制定订单计划
  const { toCancel, toPlace } = makeOrderPlan(availableOrders, targets, tolerance);
  
  // 2. 撤销不匹配的订单
  for (const order of toCancel) {
    await safeCancelOrder(/* ... */);
  }
  
  // 3. 创建新订单
  for (const target of toPlace) {
    await placeOrder(/* ... */);
  }
}
```

### 3. 事件通知
通过观察者模式实现状态变更通知：

```typescript
private emitUpdate(): void {
  const snapshot = this.buildSnapshot();
  const handlers = this.listeners.get("update");
  if (handlers) {
    handlers.forEach((handler) => handler(snapshot));
  }
}
```

## 风险控制机制

### 1. 止损检查
```typescript
private async checkRisk(position: PositionSnapshot, bidPrice: number, askPrice: number): Promise<void> {
  const triggerStop = shouldStopLoss(position, bidPrice, askPrice, this.config.lossLimit);
  
  if (triggerStop) {
    // 触发止损：撤销所有挂单并市价平仓
    await this.flushOrders();
    await marketClose(/* ... */);
  }
}
```

### 2. 限流控制
通过`RateLimitController`实现API调用频率控制，防止触发交易所限流。

## 总结

这个项目的运行流程体现了现代TypeScript/Node.js应用的典型特征：

1. **事件驱动**: 基于WebSocket实时数据推送
2. **定时循环**: 通过`setInterval`维持持续运行
3. **状态管理**: 维护复杂的交易状态
4. **模块化设计**: 清晰的职责分离
5. **错误处理**: 完善的异常处理机制

与Spring框架相比，这种架构更适合**持续运行的后台服务**场景，而不是传统的Web请求-响应模式。理解这种差异有助于更好地掌握不同类型的应用架构设计。
